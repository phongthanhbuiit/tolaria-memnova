# A03–D01 implementation checkpoint evidence

This is an implementation checkpoint, **not completion of the Memnova plan**. Migration/cutover, the maintained scheduler, durable study sessions, the page/card interface, Library onboarding and final localization/native QA are still outstanding. See `docs/MEMNOVA-IMPLEMENTATION.md`.

## Implemented

- Selective upstream editor unmount/DOM guards and Radix 1.6.1 / Virtuoso 4.18.5 dependency fixes. No bulk upstream merge. The React 19 tooltip-ref regression failed before the update and passed afterward; editor unmount and empty-answer-marker regressions also followed red/green cycles.
- Legacy scheduling now uses one validated, serialized, synced temporary-file replacement, flushes pending lesson edits first, propagates save failure and awards stats only after success. Enabling no longer resets an existing schedule. Scoped study includes the root and never falls back to another deck. Session snapshots prevent skipping cards after an index refresh; stale content loads are cancelled. Saving failure preserves the answer for retry. The due clock waits for the next due time (bounded to a minute), avoiding whole-app renders every second; a dedicated regression reproduces that performance defect.
- Per-Library UUID/SQLite storage, transactional schema initialization, future-version rejection, foreign keys, WAL, independent cards/schedules, optimistic edits, draft/clone/trash behavior, validated typed IPC and a frontend client. Markdown bytes are unchanged by card CRUD. Page IDs are registered and survive renames; writing them into existing Markdown is deferred to the backup-first importer.
- Verified online SQLite backup and fresh restore, exact Markdown/media checksums, empty folders, Library identity validation, traversal/symlink rejection, corrupted-data refusal and temporary-file cleanup. Source WAL mode remains intact. Native restore accepts a backup ID and creates a fresh directory inside the Library boundary, never a caller-supplied output path.
